# Workspace — agent rules

The machinery around the skills: the Nx workspace, the docs site, CI and the agents' own
settings. None of it ships, and none of it may reach a skill
([ADR 0002](../../doc/adr/0002-node-serves-the-repository-never-the-skills.md)). The model is
`shared-platform`'s, and so are its known departures
([ADR 0008](../../doc/adr/0008-agentic-workspace-on-the-shared-platform-model.md)).

## Nx

`nx` and `@nx/devkit` are pinned to the versions `shared-platform` uses — move them together,
in both repositories, or not at all. Two projects:

| Project | Root | Targets that matter |
| --- | --- | --- |
| `ai-skills` | `.` | `check` — the `package.json` script; `pnpm run check` is the same thing without Nx |
| `docs` | `apps/docusaurus` | `build`, `start`, `serve`, `clear`; `config-generator` and `sync-docs` are pulled in, never run by hand |

Run tasks through Nx (`pnpm nx run docs:build`), with one exception kept on purpose: the skills
gate is `pnpm run check`, because the `pre-push` hook and every repository that pins
`check-skills.sh` run it with bash alone.

`check-skills.sh` takes an optional root — `scripts/check-skills.sh [root]` — for exactly that
consumer. Without one it checks this repository. With one, a root that is not a directory or has
no `skills/` exits 2: fail-closed, because a wrong path must never read as "nothing to check".

## The docs site

`apps/docusaurus`, generated by `@fmmenchi/nx-docusaurus`
([ADR 0004](../../doc/adr/0004-a-docs-site-for-this-repository.md)). It serves `README.md`,
`doc/adr/*.md` and `skills/*/SKILL.md` **from where they are written**: one docs instance
rooted at the repository, with an allow-list in `docusaurus.config.ts`.

- **Never copy or move a file into the site.** ADRs stay in `doc/adr/`; a skill directory gains
  nothing for the site's sake, because it ships whole.
- **The allow-list and the build's cache inputs move together.** The inputs live in
  `apps/docusaurus/package.json`; a path served but not hashed is served stale from cache.
- **One instance.** A second one nested inside the first double-compiles, and the build stays
  green while the page renders as source. See `known-issues.md`.
- A broken link fails the build. Link between ADRs and skills with relative `.md` paths, as on
  GitHub; the site resolves them.

`pnpm install` needs a GitHub Packages token, because the plugin is published there. Locally:
`pnpm config set "//npm.pkg.github.com/:_authToken" <a PAT with read:packages>`, once per
machine. The reasons it is not in `.npmrc` are in `.npmrc`.

## CI

`.github/workflows/ci.yml` installs through `shared-platform`'s `setup` brick, **pinned by
commit SHA** with the tag it corresponds to in a comment. Bump it by moving both, never by
switching to a tag. It runs the definition of done — `pnpm run check`, then
`pnpm nx run docs:build` — and, on pull requests, the branch-name and commit-message gates.

The job is named `check` and the name is load-bearing: branch protection on `main` requires
it.

## Agent settings

- **`AGENTS.md` is the only contract.** Never add a `CLAUDE.md` or a symlink to one. Tools that
  default to another filename are pointed at `AGENTS.md` in their project settings
  (`.gemini/settings.json`).
- **Settings are tracked when they carry something real; state never is.** `.claude/worktrees/`,
  `.claude/settings.local.json` and `.cache/` are ignored. There is no `.claude/settings.json`
  because nothing needs to be in it — add one when something does, not before.
- **No per-tool copies of skills or rules** in `.cursor/`, `.github/`, `.opencode/` or anywhere
  else in the repository. Skills reach the tools by symlink, at user level (`install.sh`).
