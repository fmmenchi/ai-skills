# Architecture — agent rules

**Two contracts, one repository.** `contract/AGENTS.md` is the product: `install.sh` symlinks it
as `~/.claude/CLAUDE.md` and `~/.<tool>/AGENTS.md`, so it applies in every repository on the
machine. The root `AGENTS.md` governs work done *inside* here and is installed nowhere. Merging
them would install this repository's build commands into every project.
[ADR 0001](../../apps/docusaurus/docs/adr/0001-two-contracts-one-repository.md); human rationale
`../../README.md`.

**This repository is the harness of a larger programme and knows nothing of it by design.** The
programme is devmate — a product that takes a GitHub issue to a draft pull request — and its
plan, its reviews and every decision about the product live in `fmmenchi/devmate`, not here.
What reaches this repository is only what passes the admission gates below; a skill the product
needs is the product's, and goes with the product.

## Layout

| Path | Ships | Read by | Notes |
| --- | --- | --- | --- |
| `contract/AGENTS.md` | **yes**, by symlink | every tool, in every repository | the product; edit it and every tool sees the change at once |
| `skills/<name>/` | **yes**, one symlink per skill | the tool that activates it | empty is the correct state; see the admission gates below |
| `AGENTS.md` | no | agents working in this repository | hub; the spokes in `.agents/doc/` are opened on demand |
| `.agents/doc/*.md` | no | on demand, when a task touches the topic | this file and its siblings; states decisions, never makes them |
| `apps/docusaurus/docs/adr/` | no | before any structural decision, and to find why one was taken | the record; an ADR precedes the change it describes — see `workflow.md` |
| `apps/docusaurus/docs/reviews/` | no | when reviewing a skill, and to find what a review changed | reviews verbatim, with `<artefact>.record.md` beside them (ADR 0006, location by ADR 0008) |
| `evals/<name>/` | no | when writing or running a skill's evals | outside the skill, because the skill ships whole (ADR 0006); run on promptfoo (ADR 0007) |
| `scripts/check-skills.sh` | no | the `pre-push` hook, `pnpm run check`, and any repository that pins it with a root argument | the gate |
| `tools/commit/` | no | commitlint and the branch-name gate | one vocabulary, two enforcement points |
| `apps/docusaurus/` | no | `pnpm nx run @fmmenchi/ai-skills-docs:*` | the docs site; see *The docs site* below |
| `nx.json`, `pnpm-workspace.yaml`, `.npmrc` | no | Nx and pnpm | the workspace; `.npmrc` maps `@fmmenchi` to GitHub Packages |
| `.gemini/settings.json` | no | Gemini CLI | points it at `AGENTS.md`; agent settings are tracked, agent state is ignored |
| `.github/workflows/ci.yml` | no | GitHub Actions | re-runs the gates; the only one a laptop cannot skip — see `workflow.md` |
| `install.sh` | no | run by hand | idempotent; never overwrites a non-symlink |

Skills are linked **one by one**, never by linking `skills/` itself: the destination directories
already hold vendor packs, and those must survive.

## The Nx workspace

The model is `shared-platform`'s, and so are its known departures
([ADR 0008](../../apps/docusaurus/docs/adr/0008-agentic-workspace-on-the-shared-platform-model.md)).
`nx` and `@nx/devkit` are pinned to the versions `shared-platform` uses — move them together, in
both repositories, or not at all. Two projects:

| Project | Root | Targets that matter |
| --- | --- | --- |
| `ai-skills` | `.` | `check` — the `package.json` script; `pnpm run check` is the same thing without Nx |
| `@fmmenchi/ai-skills-docs` | `apps/docusaurus` | `build`, `start`, `serve`, `clear`; `config-generator` and `sync-docs` are pulled in, never run by hand |

Run tasks through Nx, with one exception kept on purpose: the skills gate is `pnpm run check`,
because the `pre-push` hook and every repository that pins `check-skills.sh` run it with bash
alone. `check-skills.sh` takes an optional root — `scripts/check-skills.sh [root]` — for exactly
that consumer. Without one it checks this repository. With one, a root that is not a directory
or has no `skills/` exits 2: fail-closed, because a wrong path must never read as "nothing to
check".

`pnpm install` needs a GitHub Packages token, because the docs plugin is published there.
Locally: `pnpm config set "//npm.pkg.github.com/:_authToken" <a PAT with read:packages>`, once
per machine. The reasons it is not in `.npmrc` are in `.npmrc`.

## The docs site

`apps/docusaurus`, generated by `@fmmenchi/nx-docusaurus`
([ADR 0004](../../apps/docusaurus/docs/adr/0004-a-docs-site-for-this-repository.md)), in the
generator's standard shape — one docs instance over the co-located `docs/` — the same as
`shared-platform` and devmate.

- **The repository's own human docs are written in the site:** ADRs in `docs/adr/`, reviews in
  `docs/reviews/`, the home page in `docs/index.md`. A new folder gets a `_category_.json`.
- **A skill is linked, never copied.** The home page links each skill to its `SKILL.md` on
  GitHub; add a row there when a skill is admitted. A skill directory gains nothing for the
  site's sake, because it ships whole. `README.md` stays at the root, where GitHub shows it.
- **A broken link fails the build** — between pages of the site. Links out to GitHub are not
  checked, which is the price of not copying the skills.

## Agent settings

- **`AGENTS.md` is the only contract.** Never add a `CLAUDE.md` or a symlink to one. Tools that
  default to another filename are pointed at `AGENTS.md` in their project settings
  (`.gemini/settings.json`).
- **Settings are tracked when they carry something real; state never is.** `.claude/worktrees/`,
  `.claude/settings.local.json` and `.cache/` are ignored. There is no `.claude/settings.json`
  because nothing needs to be in it — add one when something does, not before.
- **No per-tool copies of skills or rules** in `.cursor/`, `.github/`, `.opencode/` or anywhere
  else in the repository. Skills reach the tools by symlink, at user level (`install.sh`).
- **Generated, never edited or committed:** `.nx/`, `.cache/`, `apps/docusaurus/build/` and
  `.docusaurus/`.

## Admission — settled, don't relitigate

A skill belongs here only if **all three** hold:

1. **No vendor can write it.** Nx ships the Nx skills, Cloudflare theirs, Argent theirs. They
   arrive from their own marketplaces and are never vendored into a repository of mine.
2. **It would not change in the same pull request as a code change.** If it would, it belongs in
   that repository next to the code it describes, for the same reason tests do.
3. **It names capabilities, not vendor tools.** The file format travels between tools on its
   own; the wording decides whether the skill survives the trip. The gate warns on the usual
   offenders.

Fail any gate and it has a home already: client work in `wishew-skills`, project-scoped skills
in the project, vendor skills in the vendor's marketplace. **Say no by default** — the bar is
having explained the same thing to an agent three times.

## The Node boundary

Node is here for the repository — the commit tooling, Nx and the docs site — and nothing else.
**No skill may depend on it.** A skill is
Markdown, plus — where it needs determinism — a script that runs with what its reader already
has. The moment a skill needs `pnpm install`, it has stopped being portable, which is the one
property this repository exists to protect.

The same reasoning bounds every build step: it may serve the repository, never the skills. The
docs site reads the skills; nothing in a skill reads the site.
[ADR 0002](../../apps/docusaurus/docs/adr/0002-node-serves-the-repository-never-the-skills.md),
[ADR 0004](../../apps/docusaurus/docs/adr/0004-a-docs-site-for-this-repository.md).

## What is standard, and what is not

Normative, and the whole specification: a directory containing a file named exactly `SKILL.md`,
whose YAML frontmatter carries `name` and `description`. The filename is case-sensitive to every
tool, and macOS is not — see `known-issues.md`.

Convention, followed everywhere and enforced nowhere: the `references/` `scripts/` `assets/`
split, and the three-level loading model behind it. Treat as settled.

Everything else — the phrasing of a description, word budgets, index files, repository shape —
is preference. See `authoring.md` for the rules that do change outcomes.
